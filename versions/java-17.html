⚠ Migration watch-outs (11 → 17).
  • JDK internals strongly encapsulated by default (JEP 403) — the old --illegal-access=permit escape hatch is gone. Reflective access to internals now fails; add explicit --add-opens/--add-exports only where needed. Older bytecode libraries (ASM, cglib, Mockito) may need upgrading.
  • Security Manager deprecated for removal JEP 411; RMI Activation removed JEP 407; experimental AOT/JIT (Graal) compiler removed.
  • Always-strict floating point restored — math may differ slightly from pre-17 non-strictfp results.

1 · Language features

Switch expressions Final in 14 JEP 361

Why it matters: switch can return a value, uses arrow labels (no fall-through), and yield for blocks — eliminating a whole class of break bugs.

Before — statement, fall-through, mutable var
int days;
switch (month) {
  case JAN: case MAR: case MAY:
    days = 31; break;
  case FEB:
    days = 28; break;
  default:
    days = 30;
}
After — expression
int days = switch (month) {
  case JAN, MAR, MAY -> 31;
  case FEB           -> 28;
  default            -> 30;
};   // exhaustive, no break, single assignment

Records Final in 16 JEP 395

Why it matters: immutable data carriers with generated constructor, accessors, equals/hashCode/toString.

Before — ~40 lines
public final class Point {
  private final int x, y;
  public Point(int x, int y){this.x=x;this.y=y;}
  public int x(){return x;} public int y(){return y;}
  public boolean equals(Object o){ /* ... */ }
  public int hashCode(){ /* ... */ }
  public String toString(){ /* ... */ }
}
After
public record Point(int x, int y) { }

Sealed classes Final in 17 JEP 409

Why it matters: restrict which types may extend/implement yours, so the compiler knows the full set and can check switch exhaustiveness.

public sealed interface Shape permits Circle, Square, Rectangle { }
public record Circle(double r)              implements Shape { }
public record Square(double side)           implements Shape { }
public record Rectangle(double w, double h) implements Shape { }

Pattern matching for instanceof Final in 16 JEP 394

Before
if (obj instanceof String) {
  String s = (String) obj;   // redundant cast
  return s.length();
}
After (Java 16)
if (obj instanceof String s) {   // binds s
  return s.length();
}

2 · New & updated APIs

Stream.toList() Added in 16

Before
List<String> names = stream
    .map(User::name)
    .collect(Collectors.toList());
After (Java 16)
List<String> names = stream
    .map(User::name)
    .toList();   // shorter, unmodifiable

Stream.mapMulti — one-to-many Added in 16

Why it matters: expand each element into several without allocating an intermediate stream per element (faster than flatMap in hot paths).

Before — flatMap allocates a stream per item
users.stream()
     .flatMap(u -> u.roles().stream())
     .toList();
After (Java 16)
users.stream()
     .<Role>mapMulti((u, sink) -> u.roles().forEach(sink))
     .toList();

Compact number formatting Added in 12

Before — manual "1.2K/1M" logic
String human(long n) {
  if (n >= 1_000_000) return (n/1_000_000) + "M";
  if (n >= 1_000)     return (n/1_000) + "K";
  return String.valueOf(n);
}
After (Java 12)
var fmt = NumberFormat.getCompactNumberInstance(
    Locale.US, NumberFormat.Style.SHORT);
fmt.format(1_200);      // "1.2K"
fmt.format(3_400_000);  // "3.4M"   (locale-aware!)

Unix-domain socket channels Added in 16 JEP 380

Why it matters: fast, secure local IPC (e.g. talking to Docker or a local DB) without TCP.

var address = UnixDomainSocketAddress.of("/tmp/app.sock");
try (var channel = SocketChannel.open(StandardProtocolFamily.UNIX)) {
  channel.connect(address);
  // ... read/write like any SocketChannel
}

Enhanced pseudorandom generators Added in 17 JEP 356

Why it matters: java.util.Random locked you into one algorithm forever. The new RandomGenerator interface lets you pick from 17 built-in algorithms (including modern, statistically stronger ones like Xoshiro/L128X) through one uniform API.

Before — one fixed algorithm
Random r = new Random(42);
int x = r.nextInt(100);
// SplittableRandom / ThreadLocalRandom existed, but each has its
// own type — no common interface, can't swap algorithms easily
After — pluggable algorithm, one interface
RandomGenerator rng =
    RandomGeneratorFactory.of("Xoshiro256PlusPlus").create(42);
int x = rng.nextInt(100);
// swap "Xoshiro256PlusPlus" for "L64X128MixRandom", "Well44497b"...
// same call sites, different algorithm

RandomGeneratorFactory.all()               // discover what's available
    .map(RandomGeneratorFactory::name)
    .forEach(System.out::println);

Other API additions

// Collectors.teeing — combine two collectors in one pass (Added in 12)
var stats = nums.stream().collect(Collectors.teeing(
    Collectors.summingInt(i -> i),
    Collectors.counting(),
    (sum, count) -> "sum=" + sum + " count=" + count));

// HexFormat — bytes ↔ hex without manual loops (Added in 17)
String hex = HexFormat.of().formatHex(new byte[]{1, 2, 3});   // "010203"

// String extras: indent / transform / formatted (Added in 12 / 15)
"Hi %s".formatted("Ada");
name.transform(String::toUpperCase);

3 · Tooling

Helpful NullPointerExceptions Added in 14

Why it matters: the message names the exact expression that was null.

Before
Exception in thread "main"
  java.lang.NullPointerException
    at Order.total(Order.java:14)   // which thing was null??
After (Java 14)
NullPointerException: Cannot invoke "Item.price()"
  because "<local2>.item" is null    // names the culprit
  • jpackage Added in 16 JEP 392 — build a native, double-clickable installer from your app + a bundled JRE, so end users don't need Java installed: 
    jpackage --input target/ --name MyApp --main-jar myapp.jar \
    --main-class com.acme.Main --type dmg     # or: msi, exe, deb, rpm, pkg
# produces MyApp.dmg — a self-contained installer, no separate JRE download

4 · JVM / performance / other

  • ZGC and Shenandoah low-pause collectors reached production Added in 15.
  • Hidden classes 15 — for frameworks that generate classes at runtime (lambdas, proxies, dynamic mixins) without leaking them into the normal classloader namespace — a hidden class can't be found by name, and is garbage-collected independently of its defining loader: 
    byte[] bytecode = /* generated or loaded class bytes */;
Lookup lookup = MethodHandles.lookup().defineHiddenClass(bytecode, true);
Class<?> hidden = lookup.lookupClass();

hidden.isHidden();              // true
Class.forName(hidden.getName()); // throws ClassNotFoundException — verified:
// it genuinely cannot be looked up by name, unlike a normal generated class
    This is what frameworks like Spring, Mockito and lambda metafactories now use internally instead of leaking throwaway classes into your classloader.
  • Strong encapsulation of JDK internals by default 16 JEP 396 (Java 16 — warnings) JEP 403 (Java 17 — enforced) — run jdeps --jdk-internals before upgrading.
  • macOS/AArch64 (Apple Silicon) port JEP 391 and a new Metal-based macOS rendering pipeline Added in 17 JEP 382. Applet API deprecated for removal JEP 398.
  • EdDSA signatures 15 JEP 339; context-specific deserialization filters 17.
  • Foreign Function & Memory API begins incubating 17 → FFM deep-dive.
