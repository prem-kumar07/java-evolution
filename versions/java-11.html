Java 11 LTS

The first LTS after 8 and the baseline most teams migrated to. Headliners: var (introduced in 10), the standard HttpClient, running a single source file without compiling, and a batch of convenient String/Files/Collection methods.

⚠ Migration watch-outs (8 → 11).
  • Java EE & CORBA modules removed JEP 320 — java.xml.bind (JAXB), java.xml.ws (JAX-WS), java.activation, java.corba are gone. Add them as explicit Maven/Gradle dependencies. The #1 upgrade break from 8.
  • JavaFX is no longer bundled — use OpenJFX as a separate dependency.
  • Nashorn JavaScript engine deprecated (removed in 15).
  • No more JRE / Server JRE downloads — ship a runtime with jlink.

1 · Language features

var — local-variable type inference Added in 10

Why it matters: drops the redundant left-hand type when it's obvious from the initializer. It's still static typing — no runtime cost.

Before
Map<String, List<Integer>> scores =
    new HashMap<String, List<Integer>>();
for (Map.Entry<String, List<Integer>> e : scores.entrySet()) { }
After (Java 10)
var scores = new HashMap<String, List<Integer>>();
for (var e : scores.entrySet()) { }   // type inferred

Full rules → var deep-dive.

var in lambda parameters Added in 11 JEP 323

Why it matters: lets you put annotations/modifiers on inferred lambda parameters.

Before — no place for the annotation
map.forEach((k, v) -> use(k, v));
// can't annotate k or v
After (Java 11)
map.forEach((@NonNull var k, @NonNull var v) -> use(k, v));

Nest-based access control Added in 11 JEP 181

Why it matters: the Java source for a nested class accessing an outer class's private member always looked the same — but before 11, the compiler had to generate a hidden synthetic package-private accessor method to make that legal at the bytecode level (JVMs only understood per-class access, not per-source-file nest). Java 11 taught the JVM the concept of a "nest" directly, so no synthetic bridge methods are generated, and reflection can now correctly enumerate nestmates.

public class Outer {
  private int secret = 42;
  class Inner { int reveal() { return secret; } }   // compiles the same in 8 and 11...

  public static void main(String[] args) {
    System.out.println(new Outer().new Inner().reveal());   // 42
    // ...but the JVM's view of the relationship changed:
    for (Class<?> c : Outer.class.getNestMembers())
      System.out.println("nestmate: " + c.getName());
  }
}
// nestmate: Outer
// nestmate: Outer$Inner        (verified output)

Class.getNestMembers() and Class.getNestHost() Added in 11 are the new reflection APIs that expose this relationship directly.

2 · New & updated APIs

Standard HTTP Client — java.net.http JEP 321

Why it matters: a modern client with HTTP/2, WebSocket and async support, replacing the clunky HttpURLConnection (incubated in 9, standard in 11).

Before — HttpURLConnection
URL url = new URL("https://api.example.com");
HttpURLConnection c = (HttpURLConnection) url.openConnection();
c.setRequestMethod("GET");
try (var in = new BufferedReader(
        new InputStreamReader(c.getInputStream()))) {
  String body = in.lines().collect(joining("\n"));
}
After — HttpClient
HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com")).build();
HttpResponse<String> res =
    client.send(req, BodyHandlers.ofString());
String body = res.body();
// async: client.sendAsync(req, BodyHandlers.ofString())
//              .thenApply(HttpResponse::body);

New String methods

Before — hand-rolled helpers
boolean blank = s.trim().isEmpty();
String bar = String.join("", Collections.nCopies(20, "="));
for (String line : text.split("\\R")) process(line);
After (Java 11)
boolean blank = s.isBlank();
String bar = "=".repeat(20);
text.lines().forEach(this::process);
" hi ".strip();   // Unicode-aware (trim() is ASCII-only)

Files: read/write a whole string in one call

Before
byte[] bytes = Files.readAllBytes(path);
String text = new String(bytes, StandardCharsets.UTF_8);
Files.write(path, text.getBytes(StandardCharsets.UTF_8));
After (Java 11)
String text = Files.readString(path);
Files.writeString(path, text);

Immutable copies & unmodifiable collectors Added in 10

Before
List<String> snapshot =
    Collections.unmodifiableList(new ArrayList<>(src));
List<String> names = stream
    .map(User::name)
    .collect(collectingAndThen(toList(),
             Collections::unmodifiableList));
After (Java 10)
List<String> snapshot = List.copyOf(src);       // immutable copy
List<String> names = stream
    .map(User::name)
    .collect(toUnmodifiableList());              // + toUnmodifiableSet/Map

Other handy additions

Before
if (!opt.isPresent()) handleEmpty();
User u = opt.orElseThrow(() -> new NoSuchElementException());
String[] arr = list.toArray(new String[0]);
list.removeIf(s -> s == null || s.isBlank());
After
if (opt.isEmpty()) handleEmpty();          // Added in 11
User u = opt.orElseThrow();                 // Added in 10 (no-arg)
String[] arr = list.toArray(String[]::new); // Added in 11
list.removeIf(Predicate.not(String::isBlank)); // Predicate.not, Added in 11

3 · Tooling

Run a single source file — no compile step JEP 330

Why it matters: scripting in Java without a build tool or .class files.

Before
javac Hello.java   // -> Hello.class
java Hello
After (Java 11)
java Hello.java    // compiles + runs in one step
java Hello.java arg1 arg2
  • Flight Recorder (JFR) JEP 328 — low-overhead production profiling, previously a paid Oracle-JDK-only feature, now open-source and built into every JDK: 
    // record for 60s starting at JVM launch
java -XX:StartFlightRecording=duration=60s,filename=app.jfr -jar app.jar

// or control it live on a running JVM by PID, no restart needed
jcmd <pid> JFR.start duration=60s filename=app.jfr
jcmd <pid> JFR.dump filename=snapshot.jfr
jcmd <pid> JFR.stop
    Open the resulting .jfr file in JDK Mission Control to see CPU, allocation, GC and lock-contention data with near-zero overhead.
  • Application Class-Data Sharing Added in 10 — share class metadata across JVMs to cut startup time.

4 · JVM / performance / other

  • ZGC (experimental) JEP 333 & Epsilon (no-op) JEP 318 garbage collectors introduced.
  • Parallel full GC for G1 Added in 10 — shorter worst-case pauses.
  • TLS 1.3 support. JEP 332
  • Time-based release versioning Added in 10 and root certificates shipped with OpenJDK.
  • Oracle JDK & OpenJDK builds became functionally identical.
