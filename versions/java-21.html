1 · Language features

Virtual threads Final in 21

Why it matters: write simple blocking code that scales to millions of concurrent tasks — the runtime frees the OS thread while a virtual thread waits.

Before — bounded pool
var pool = Executors.newFixedThreadPool(200);
for (var task : tasks) pool.submit(task);
// ~200 concurrent; more = queueing or OOM
After — one virtual thread per task
try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
  for (var task : tasks) ex.submit(task);
}   // millions of concurrent blocking tasks, cheap

Architecture, pinning, Spring Boot, migration → Virtual threads deep-dive.

Pattern matching for switch Final in 21

Before — if/else chain of casts
String s;
if (obj instanceof Integer i)       s = "int " + i;
else if (obj instanceof String str) s = "str " + str;
else                                s = "other";
After — type patterns + guards
String s = switch (obj) {
  case Integer i when i > 100 -> "big int " + i;
  case Integer i              -> "int " + i;
  case String str             -> "str " + str;
  default                     -> "other";
};

Record patterns Final in 21

Before
if (obj instanceof Point p) {
  int x = p.x();
  int y = p.y();
}
After — destructure (nested)
if (obj instanceof Point(int x, int y)) { }
switch (shape) {
  case Line(Point(var x1,var y1), Point(var x2,var y2)) -> ...;
}

2 · New & updated APIs

Sequenced collections Added in 21

Why it matters: before, every ordered collection expressed "first/last/reverse" differently — and LinkedHashSet had no clean "last" at all. New interfaces (SequencedCollection, SequencedSet, SequencedMap) give a uniform vocabulary.

Before — inconsistent, awkward
list.get(0);                 // first
list.get(list.size() - 1);   // last
var copy = new ArrayList<>(list);
Collections.reverse(copy);   // reversed
// LinkedHashSet: no direct "last" — must iterate
After — SequencedCollection
list.getFirst();  list.getLast();
list.addFirst(x); list.addLast(y);
List<T> rev = list.reversed();     // reversed view
// same on SequencedSet / SequencedMap:
map.firstEntry(); map.lastEntry(); map.reversed();

Key Encapsulation Mechanism (KEM) API Added in 21

Why it matters: a KEM lets two parties agree on a shared secret using only public keys — no separate key-exchange protocol needed. It's the standard building block behind post-quantum algorithms like ML-KEM (final in 24).

// Receiver: generate a key pair, publish the public key
KeyPairGenerator g = KeyPairGenerator.getInstance("ML-KEM");
KeyPair kp = g.generateKeyPair();

// Sender: derive a shared secret using the receiver's public key
KEM kemS = KEM.getInstance("ML-KEM");
KEM.Encapsulator enc = kemS.newEncapsulator(kp.getPublic());
KEM.Encapsulated encapsulated = enc.encapsulate();
SecretKey senderSecret = encapsulated.key();
byte[] toSend = encapsulated.encapsulation();   // send this to the receiver

// Receiver: recover the SAME shared secret from the encapsulation
KEM kemR = KEM.getInstance("ML-KEM");
KEM.Decapsulator dec = kemR.newDecapsulator(kp.getPrivate());
SecretKey receiverSecret = dec.decapsulate(toSend);
// verified: senderSecret and receiverSecret are byte-for-byte identical

3 · Tooling

Code snippets in Javadoc — @snippet Added in 18

Why it matters: old {@code ...} examples were plain text — never compiled, so they rotted. @snippet examples are real, can be validated against actual source files, and support highlighting/regions.

Before — {@code}, unchecked plain text
/**
 * Example:
 * <pre>{@code
 *   var list = List.of(1, 2, 3);
 *   int sum = list.stream().mapToInt(i -> i).sum();
 * }</pre>
 */
After — @snippet (validated, highlightable)
/**
 * Example:
 * {@snippet :
 *   var list = List.of(1, 2, 3);      // @highlight substring="List"
 *   int sum = list.stream().mapToInt(i -> i).sum();
 * }
 */
// or pull from a real file:  {@snippet file="Demo.java" region="sum"}

Simple Web Server & Generational ZGC

  • Simple Web Server Added in 18 — a zero-config static file server for testing/prototyping: 
    jwebserver -p 8000 -d /path/to/site
  • Generational ZGC Added in 21 — ZGC now keeps a young generation, improving throughput: -XX:+UseZGC -XX:+ZGenerational.

4 · JVM / performance / other

  • UTF-8 is the default charset Added in 18 — file I/O no longer depends on the platform locale. Watch behaviour changes in old code.
  • Finalization deprecated for removal Added in 18 — Object.finalize() was slow, ran on an unpredictable thread, and could resurrect "dead" objects. Migrate to try-with-resources (preferred) or java.lang.ref.Cleaner when you truly need cleanup tied to garbage collection instead of an explicit scope: 
    class NativeResource implements AutoCloseable {
  private static final Cleaner CLEANER = Cleaner.create();
  private final Cleaner.Cleanable cleanable;

  NativeResource() {
    cleanable = CLEANER.register(this, () -> System.out.println("native resource freed"));
  }
  public void close() { cleanable.clean(); }   // explicit — preferred
}
try (var r = new NativeResource()) { /* use it */ }
// prints "native resource freed" — verified; also runs automatically
// if close() is never called and the object becomes unreachable
  • Core reflection reimplemented on method handles 18 — faster reflective calls, internal change.
  • Internet-address resolution SPI 18 — pluggable host resolution (custom DNS).
  • Linux/RISC-V port Added in 19.
