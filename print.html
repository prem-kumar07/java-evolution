Set up your machine

Quick start & tooling

Install one or more JDKs, switch between them, and learn the fastest ways to try features — JShell, single-file programs, preview features and incubator modules.

1 · Install a JDK

Pick a build of OpenJDK. Any of these give you the same language; they differ in support/branding:

  • Eclipse Temurin (Adoptium) — the popular community default.
  • Oracle JDK — Oracle's build.
  • Amazon Corretto, Azul Zulu, Microsoft / Liberica — vendor builds, often with extras.

Verify what you have:

java -version      # runtime version
javac -version     # compiler version
java --list-modules | head   # JDK modules available

2 · Install & switch between versions

You will want several JDKs installed at once (e.g. 17, 21, 25). Use a version manager.

SDKMAN! (macOS / Linux / WSL) — recommended

curl -s "https://get.sdkman.io" | bash        # install SDKMAN
sdk list java                                  # see available builds
sdk install java 25-tem                        # install Temurin 25
sdk install java 21.0.5-tem
sdk use java 25-tem        # switch for THIS shell only
sdk default java 21.0.5-tem   # set the global default

jenv (per-directory switching)

brew install jenv
jenv add /Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home
jenv global 21       # default
jenv local 25        # pin THIS project (writes .java-version)

Homebrew (macOS)

brew install openjdk@25 openjdk@21 openjdk@17

Manual — set JAVA_HOME

macOS / Linux (bash/zsh)
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
export PATH="$JAVA_HOME/bin:$PATH"
# Linux: JAVA_HOME=/usr/lib/jvm/temurin-25
Windows (PowerShell)
$env:JAVA_HOME = "C:\Program Files\Java\jdk-25"
$env:Path = "$env:JAVA_HOME\bin;" + $env:Path

3 · JShell — the Java REPL Added in 9

The fastest way to try a snippet without a class, main, or compile step.

jshell                    # start the REPL
jshell> var xs = List.of(1, 2, 3)
xs ==> [1, 2, 3]
jshell> xs.stream().mapToInt(i -> i).sum()
$2 ==> 6
jshell> /exit

# useful commands
jshell> /vars      /methods     /imports     /list
jshell> /save mysession.jsh    # save your session
jshell --enable-preview        # REPL with preview features on
Tip. Pipe a script in: jshell myscript.jsh, or feed stdin with echo 'System.out.println("hi")' | jshell -.

4 · Run a single source file — no compile step Added in 11

Since Java 11 (JEP 330) you can run a .java file directly; the JDK compiles it in memory.

Before — compile then run
// Hello.java
public class Hello {
  public static void main(String[] a) {
    System.out.println("Hi");
  }
}
// terminal:
javac Hello.java   // -> Hello.class
java Hello
After — run directly
// Hello.java  (same file)
java Hello.java    // compiles + runs in one step

// pass args after the file name:
java Hello.java arg1 arg2

Multi-file source programs Added in 22

JEP 458 extended this: if the file you launch references other .java files in the same source tree, they are compiled on demand too — no build tool for small programs.

java Main.java     # also compiles Helper.java, model/User.java, ... as needed

Shebang scripts

Make a Java file executable like a shell script (the file need not end in .java):

#!/usr/bin/env java --source 25
public class App {
  public static void main(String[] a) { System.out.println("script!"); }
}
// then:  chmod +x app  &&  ./app

5 · Try preview language features

A preview feature is a finished-but-not-permanent language/VM feature. You must opt in at both compile and run time, and pass --release matching your JDK. Examples in this guide that are still preview show a Preview badge.

Compile with preview
javac --release 25 --enable-preview Demo.java
Run with preview
java --enable-preview Demo

# single-file shortcut (compile+run together):
java --enable-preview --source 25 Demo.java
Gotcha. A class file compiled with --enable-preview is tied to that exact JDK version and refuses to run on any other. Preview APIs/syntax can change or be removed in the next release — never ship them to production.

6 · Try incubator modules

An incubator module is a non-final API (a whole library, e.g. the Vector API) shipped under a jdk.incubator.* module. You add the module rather than flip a preview flag.

// compile & run code that uses jdk.incubator.vector
javac --add-modules jdk.incubator.vector Simd.java
java  --add-modules jdk.incubator.vector Simd

// see all incubator modules in your JDK:
java --list-modules | grep incubator

September 2017

Java 9

The big one: the module system (JPMS) reorganised the JDK itself. Also arrived: JShell, collection factory methods, a reactive Flow API, and many smaller language tidy-ups.

⚠ Migration watch-outs (8 → 9).
  • Strong encapsulation of JDK internals — reflective access to sun.*/internal APIs now warns (and later fails). Run jdeps --jdk-internals your.jar first.
  • Split packages are illegal on the module path — two JARs sharing a package break.
  • _ is no longer a valid identifier.
  • New version string (9, not 1.9) — regexes that parsed 1.x break.
  • Applet API and several GC flag combinations deprecated.

1 · Language features

Private methods in interfaces

Interfaces got default methods in Java 8; now they can share code through private (and private static) helpers.

Before (Java 8)
interface Logger {
  default void info(String m)  { log("INFO", m); }
  default void error(String m) { log("ERROR", m); }
  // no way to hide this shared helper
  default void log(String lvl, String m) {
    System.out.println(lvl + ": " + m);
  }
}
After (Java 9)
interface Logger {
  default void info(String m)  { log("INFO", m); }
  default void error(String m) { log("ERROR", m); }
  private void log(String lvl, String m) {   // hidden
    System.out.println(lvl + ": " + m);
  }
}

Try-with-resources on effectively-final variables

Before
// must declare a fresh variable inside the ()
try (BufferedReader r = reader) {
  ...
}
After (Java 9)
BufferedReader reader = ...;   // effectively final
try (reader) {                 // use it directly
  ...
}

Diamond with anonymous classes · @SafeVarargs on private methods · _ banned

Callable<String> c = new Callable<>() { ... };  // diamond now allowed here
@SafeVarargs private void f(List<String>... xs) { }   // allowed on private methods
int _ = 3;   // COMPILE ERROR: '_' is now a reserved name (paving way for future use)

2 · New & updated APIs

Immutable collection factory methods

Before
List<String> list = Collections.unmodifiableList(
    Arrays.asList("a", "b", "c"));
Map<String,Integer> m = new HashMap<>();
m.put("a", 1); m.put("b", 2);
m = Collections.unmodifiableMap(m);
After
List<String>  list = List.of("a", "b", "c");
Set<String>   set  = Set.of("a", "b");
Map<String,Integer> m = Map.of("a", 1, "b", 2);
// truly immutable, null-hostile, compact

Stream additions: takeWhile, dropWhile, ofNullable, ranged iterate

Before
// stop at first element ≥ 5 — awkward
list.stream()
    .filter(x -> x < 5)   // keeps ALL <5, not just the leading run
    ...;
After (Java 9)
list.stream().takeWhile(x -> x < 5);   // leading run only
list.stream().dropWhile(x -> x < 5);   // skip leading run
Stream.ofNullable(maybeNull);          // 0- or 1-element stream
Stream.iterate(1, n -> n < 100, n -> n * 2);  // for-style with predicate

Optional: ifPresentOrElse, or, stream

opt.ifPresentOrElse(this::use, this::handleEmpty);   // no more if/else on isPresent()
Optional<User> u = primary.or(() -> fallbackLookup());  // lazy fallback
List<User> users = optionals.stream().flatMap(Optional::stream).toList();  // drop empties

Process API — inspect & control OS processes

ProcessHandle self = ProcessHandle.current();
System.out.println(self.pid());
ProcessHandle.allProcesses()
    .filter(p -> p.info().command().isPresent())
    .forEach(p -> System.out.println(p.pid() + " " + p.info().command().get()));

Reactive Streams — java.util.concurrent.Flow

Standard interfaces (Publisher, Subscriber, Processor, Subscription) for back-pressured async streams — the basis libraries like RxJava/Reactor interoperate with.

September 2018 · LTS

Java 11 LTS

The first LTS after 8 and the baseline most teams migrated to. Headliners: var (introduced in 10), the standard HttpClient, running a single source file without compiling, and a batch of convenient String/Files methods.

Folded in: features from Java 10 are included here and tagged, since 10 was a non-LTS stepping-stone.
⚠ Migration watch-outs (8 → 11).
  • Java EE & CORBA modules removed — java.xml.bind (JAXB), java.xml.ws (JAX-WS), java.activation, java.corba are gone. Add them as explicit Maven/Gradle dependencies. This is the #1 upgrade break from 8.
  • JavaFX is no longer bundled — use OpenJFX as a separate dependency.
  • Nashorn JavaScript engine deprecated (removed in 15).
  • No more JRE / Server JRE downloads — ship a runtime with jlink.
  • Single JDK: Oracle JDK and OpenJDK are functionally identical (licensing differs).

1 · Language features

var — local-variable type inference Added in 10

Before
Map<String, List<Integer>> scores = new HashMap<String, List<Integer>>();
for (Map.Entry<String, List<Integer>> e : scores.entrySet()) { ... }
After (Java 10)
var scores = new HashMap<String, List<Integer>>();
for (var e : scores.entrySet()) { ... }   // type inferred

Full rules, where it works and where it doesn't → var deep-dive.

var in lambda parameters Added in 11

Lets you attach annotations/modifiers to inferred lambda params.

list.forEach((var x) -> System.out.println(x));
map.forEach((@NonNull var k, @NonNull var v) -> ...);   // annotations now possible

2 · New & updated APIs

Standard HTTP Client — java.net.http

Modern client with HTTP/2, WebSocket and async support; replaces the clunky HttpURLConnection (incubated in 9, standard in 11).

Before — HttpURLConnection
URL url = new URL("https://api.example.com");
HttpURLConnection c = (HttpURLConnection) url.openConnection();
c.setRequestMethod("GET");
try (var in = new BufferedReader(
        new InputStreamReader(c.getInputStream()))) {
  String body = in.lines().collect(joining("\n"));
}
After — HttpClient
HttpClient client = HttpClient.newHttpClient();
HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com")).build();
HttpResponse<String> res =
    client.send(req, BodyHandlers.ofString());
String body = res.body();
// or async: client.sendAsync(req, ...).thenApply(...)

New String methods

"  ".isBlank();              // true
" hi ".strip();              // "hi"  (Unicode-aware; trim() is not)
"=".repeat(20);              // "===================="
"a\nb\nc".lines()            // Stream<String> of lines
        .forEach(System.out::println);

Files: read/write a whole string in one call

Before
byte[] bytes = Files.readAllBytes(path);
String text = new String(bytes, StandardCharsets.UTF_8);
Files.write(path, text.getBytes(StandardCharsets.UTF_8));
After (Java 11)
String text = Files.readString(path);
Files.writeString(path, text);

Other handy additions

Optional.isEmpty();                       // Added in 11 (complements isPresent)
opt.orElseThrow();                        // Added in 10: throws if empty, no arg
List.copyOf(other);                       // Added in 10: immutable copy

Predicate.not(String::isBlank);           // Added in 11

September 2021 · LTS

Java 17 LTS

A landmark LTS. Over 12–17 the language gained modern data modelling — records, sealed classes, switch expressions, text blocks and pattern matching — turning verbose boilerplate into a few readable lines.

Folded in: features from 12 13 14 15 16 are included and tagged with the version that introduced them.
⚠ Migration watch-outs (11 → 17).
  • JDK internals are strongly encapsulated by default (JEP 403) — the old --illegal-access=permit escape hatch is gone. Reflective access to internals now fails; add explicit --add-opens/--add-exports only where needed. Older bytecode-manipulation libs (ASM, cglib, Mockito) may need upgrading.
  • Security Manager deprecated for removal — plan to migrate off it.
  • RMI Activation removed; experimental AOT/JIT (Graal) compiler removed.
  • Always-strict floating point restored — results may differ slightly from pre-17 non-strictfp math.

1 · Language features

Switch expressions Final in 14

switch can return a value, uses arrow labels (no fall-through), and yield for blocks.

Before — statement, fall-through, mutable var
int days;
switch (month) {
  case JAN: case MAR: case MAY:
    days = 31; break;
  case FEB:
    days = 28; break;
  default:
    days = 30;
}
After — expression
int days = switch (month) {
  case JAN, MAR, MAY -> 31;
  case FEB           -> 28;
  default            -> 30;
};    // exhaustive, no break, one assignment

Records Final in 16

Before — ~40 lines of boilerplate
public final class Point {
  private final int x, y;
  public Point(int x, int y){this.x=x;this.y=y;}
  public int x(){return x;} public int y(){return y;}
  public boolean equals(Object o){ /* ... */ }
  public int hashCode(){ /* ... */ }
  public String toString(){ /* ... */ }
}
After
public record Point(int x, int y) { }
// constructor, x()/y(), equals, hashCode,
// toString — all generated.

Everything about records → Records deep-dive.

Sealed classes Final in 17

Restrict which types may extend/implement yours — the compiler then knows the full set.

public sealed interface Shape permits Circle, Square, Rectangle { }
public record Circle(double r) implements Shape { }
public record Square(double side) implements Shape { }
public record Rectangle(double w, double h) implements Shape { }

Full rules (permits, final/sealed/non-sealed) → Sealed classes deep-dive.

September 2023 · LTS

Java 21 LTS

The concurrency-defining LTS. Virtual threads make blocking code scale to millions of tasks, while pattern matching for switch and record patterns complete Java's data-oriented programming story.

Folded in: features from 18 19 20 are included and tagged.
⚠ Migration watch-outs (17 → 21).
  • UTF-8 is the default charset since 18 — code that relied on the platform default (file reads/writes, new String(bytes)) can change behaviour. Set charsets explicitly.
  • Virtual-thread pinning: on 21–23, blocking inside a synchronized block pins the carrier thread and can starve the pool. Prefer ReentrantLock around blocking I/O (fixed in 24).
  • Dynamic loading of agents warns — attaching agents at runtime is on the way to being disallowed.
  • Finalization deprecated for removal 18 — migrate to Cleaner.
  • String templates that you may have tried in 21 previews were later withdrawn — don't depend on them.

1 · Language features

Virtual threads Final in 21

Lightweight threads managed by the JVM. Write simple blocking code; the runtime handles the scale.

Before — thread pool, limited
var pool = Executors.newFixedThreadPool(200);
for (var task : tasks) pool.submit(task);
// ~200 concurrent; more = queueing or OOM
After — one virtual thread per task
try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
  for (var task : tasks) ex.submit(task);
}   // millions of concurrent blocking tasks, cheap

How they work, pinning, and when to use them → Virtual threads deep-dive.

Pattern matching for switch Final in 21

Before — if/else chain of casts
String s;
if (obj instanceof Integer i)      s = "int " + i;
else if (obj instanceof String str) s = "str " + str;
else                                s = "other";
After — type patterns + guards
String s = switch (obj) {
  case Integer i when i > 100 -> "big int " + i;
  case Integer i              -> "int " + i;
  case String str             -> "str " + str;
  default                     -> "other";
};

Record patterns Final in 21

Destructure records directly in instanceof and switch, nesting freely.

Before
if (obj instanceof Point p) {
  int x = p.x();
  int y = p.y();
  ...
}
After
if (obj instanceof Point(int x, int y)) {
  ...   // x and y bound directly
}
// nested:
switch (shape) {

var — local-variable type inference Java 10

var lets the compiler infer a local variable's type from its initializer. It is syntactic sugar, not dynamic typing — the variable still has one fixed, static type; you just don't write it out.

Why it exists

To cut noise where the type is already obvious from the right-hand side, especially with long generic types. It never changes runtime behaviour or performance.

Before
ByteArrayOutputStream out = new ByteArrayOutputStream();
Map<String, List<Customer>> byCity = new HashMap<String, List<Customer>>();
for (Map.Entry<String, List<Customer>> e : byCity.entrySet()) { }
After
var out = new ByteArrayOutputStream();
var byCity = new HashMap<String, List<Customer>>();
for (var e : byCity.entrySet()) { }

Where you can use it

var x = 10;                         // local variable with initializer
var list = List.of("a", "b");       // inferred List<String>
for (var s : list) { }              // enhanced-for loop variable
for (var i = 0; i < 10; i++) { }    // classic for-loop index
try (var in = Files.newInputStream(p)) { }   // try-with-resources
list.forEach((var s) -> print(s));  // lambda parameter (Java 11+)

Where you cannot use it

var x;                      // ✗ no initializer — nothing to infer
var y = null;               // ✗ null has no type
var f = () -> 42;           // ✗ lambda needs a target type
var arr = { 1, 2, 3 };      // ✗ array initializer needs a type
public var field = 1;       // ✗ fields cannot use var
var method() { }            // ✗ method return types cannot use var
void m(var p) { }           // ✗ method parameters cannot use var

var is local variables only: locals, loop variables, try-with-resources, and lambda params.

Rules & gotchas

  • It's still static typing. var s = "hi"; makes s a String forever — s = 42; won't compile.
  • Inferred type = the initializer's type, which may be more specific than you want: 
    var list = new ArrayList<String>();   // type is ArrayList<String>, not List<String>
    If you need the interface type, declare it explicitly.
  • Diamond + var: var m = new HashMap<>(); infers HashMap<Object,Object> — usually not what you want. Give type args on the right.
  • var is not a keyword — it's a reserved type name, so existing variables/methods named var still compile. You cannot name a class var.
  • Readability: prefer it when the type is obvious from the RHS (new, factory methods). Avoid it when the RHS hides the type (e.g. var result = process();).
var vs. Object: var keeps the precise static type (all methods available); Object o = ... erases it (only Object methods). They are completely different.

  • ✅ locals, for/for-each vars, try-with-resources, lambda params (11+)
  • ❌ fields, method params/returns, no-initializer, null, bare lambdas/arrays
  • Static type = type of the initializer. Not dynamic. No runtime cost.

Records Java 16

A record is a concise, immutable, transparent carrier for a fixed set of values. You declare the components; the compiler generates the constructor, accessors, equals, hashCode and toString.

Why it exists

Most "data classes" are pure boilerplate that's easy to get subtly wrong (a forgotten field in equals). Records make the boilerplate correct and automatic, and signal intent: "this is just data".

Before
public final class Point {
  private final int x, y;
  public Point(int x, int y) { this.x = x; this.y = y; }
  public int x() { return x; }
  public int y() { return y; }
  @Override public boolean equals(Object o) {
    if (!(o instanceof Point p)) return false;
    return x == p.x && y == p.y;
  }
  @Override public int hashCode() { return Objects.hash(x, y); }
  @Override public String toString() {
    return "Point[x=" + x + ", y=" + y + "]";
  }
}
After
public record Point(int x, int y) { }

What the compiler generates

  • A canonical constructor with all components.
  • A public accessor per component: x(), y() (no get prefix).
  • equals / hashCode based on all components.
  • toString like Point[x=1, y=2].
  • A private final field per component; the class is final.

Customising records

Compact canonical constructor — validate / normalise

public record Range(int lo, int hi) {
  public Range {                     // no parameter list, no field assignments
    if (lo > hi) throw new IllegalArgumentException("lo > hi");
    // you may reassign params to normalise; fields are set for you afterwards
  }
}

Extra members that are allowed

public record Point(int x, int y) {
  static final Point ORIGIN = new Point(0, 0);   // static fields OK
  public double distanceTo(Point o) {            // instance methods OK
    return Math.hypot(x - o.x, y - o.y);
  }
  public Point {                                 // additional constructors OK (must delegate)
  }
  public Point(int v) { this(v, v); }            // extra constructor
}

Rules & gotchas

  • Immutable & final: components are final; a record can't extend anything (it implicitly extends java.lang.Record), but it can implements interfaces.
  • No instance fields beyond components. You can't add extra non-static state.
  • "Shallowly" immutable: a component of type List can still be mutated through its reference. Defensively copy in the compact constructor if you need deep immutability: 
    public record Team(String name, List<String> members) {
  public Team { members = List.copyOf(members); }   // defensive copy
}
  • Great with pattern matching — records can be destructured (record patterns, Java 21). See Pattern matching.
  • Serialization is driven by the components and the canonical constructor (so validation runs on deserialize — safer than normal classes).

Local records & nested records

List<Order> top = orders.stream().map(o -> {
  record Scored(Order order, double score) { }     // local record inside a method
  return new Scored(o, rank(o));
}).sorted(comparingDouble(Scored::score)).map(Scored::order).toList();

Sealed classes & interfaces Java 17

A sealed type explicitly lists which classes may extend or implement it. This gives you a closed, known set of subtypes — the foundation for exhaustive pattern matching and safe modelling of "one of a fixed set of shapes".

Why it exists

Before, a type was either final (no subtypes) or fully open (anyone, anywhere could subclass). There was no way to say "these three and no others". Sealed types fill that gap and let the compiler reason about the complete hierarchy.

Before — open, or a hand-rolled enum-of-classes
public abstract class Shape { }
// anyone can extend Shape anywhere — the compiler
// can never know the full list, so switches always
// need a default and can silently miss a new case.
After — sealed
public sealed interface Shape
    permits Circle, Square, Rectangle { }

public record Circle(double r)             implements Shape { }
public record Square(double side)          implements Shape { }
public record Rectangle(double w, double h) implements Shape { }

The three choices every permitted subtype must make

A class that extends a sealed type must itself declare how its hierarchy continues:

public sealed interface Shape permits Circle, Quadrilateral { }

public final     record Circle(double r) implements Shape { }   // final: no further subtypes
public sealed    interface Quadrilateral extends Shape
                 permits Square, Rectangle { }                  // sealed: continues the closed set
public non-sealed class Rectangle implements Quadrilateral { }  // non-sealed: re-opens for anyone
ModifierMeaning
finalLeaf — cannot be extended further.
sealedContinues the closed hierarchy with its own permits.
non-sealedDeliberately re-opens the type to unrestricted extension.

Rules

  • Permitted subtypes must be accessible to the sealed type and, unless in the same file, in the same module (or same package for the unnamed module).
  • You may omit permits if all subtypes are in the same source file — the compiler infers them: 
    sealed interface Expr permits Num, Add { }   // permits optional if all are below in this file
record Num(int v) implements Expr { }
record Add(Expr l, Expr r) implements Expr { }
  • Every permitted subtype must directly extend/implement the sealed type.
  • Records are implicitly final, so they fit permitted lists perfectly.

The payoff: exhaustive switches

Because the compiler knows every subtype, a switch over a sealed type needs no default — and if you later add a subtype, every switch that didn't handle it fails to compile. Compile-time safety instead of a silent runtime bug.

Before — needs default, misses new cases silently
double area(Shape s) {
  if (s instanceof Circle c) return Math.PI*c.r()*c.r();
  if (s instanceof Square sq) return sq.side()*sq.side();
  throw new IllegalStateException("unknown shape"); // runtime!
}
After — exhaustive, checked at compile time
double area(Shape s) {
  return switch (s) {              // no default needed
    case Circle c      -> Math.PI * c.r() * c.r();
    case Square sq     -> sq.side() * sq.side();
    case Rectangle r   -> r.w() * r.h();
  };
}
Sealed + records + pattern matching = "algebraic data types". Model a closed set of cases as sealed records, then switch over them exhaustively — the modern, type-safe alternative to the visitor pattern. See Pattern matching.

3 · Pattern matching for switch Java 21

String describe(Object o) {
  return switch (o) {
    case null            -> "null";                 // null can be a case
    case Integer i when i < 0 -> "negative int";    // guarded pattern
    case Integer i       -> "int " + i;
    case String s        -> "string of " + s.length();
    case int[] arr       -> "array len " + arr.length;
    default              -> "something else";
  };
}
  • Guards use when. Order matters — the first matching label wins.
  • null handling: add case null to handle it (otherwise a null selector throws NullPointerException, as before).
  • Exhaustiveness: over a sealed type or enum, the compiler verifies all cases are covered — no default needed. See Sealed classes.

How indentation works (incidental whitespace)

The compiler finds the line with the least leading whitespace (including the closing """) and strips that much from every line. So you can indent the block to match your code without it appearing in the string.

String s = """
        one
          two
        """;
// result: "one\n  two\n"  — the common 8-space margin is removed,
// the extra 2 spaces before "two" are kept.

Key rules

  • The opening """ must be followed by a newline — content starts on the next line.
  • Where the closing """ sits controls the common indentation and whether there's a trailing newline.
  • No need to escape "; escape only """ if it appears literally.
  • You can still use escapes like \t, \n, and \uXXXX.

Two special escapes for text blocks

// \  (backslash at end of line) — suppress the line break
String oneLine = """
    Lorem ipsum dolor \
    sit amet""";              // "Lorem ipsum dolor sit amet"

// \s — a literal space that is NOT stripped as trailing whitespace
String padded = """
    key =\s
    """;                      // keeps the trailing space after '='
Great for: SQL, JSON, HTML, regexes, embedded scripts, test fixtures — anything multi-line. Combine with String.formatted(...) for templating (Java's dedicated string-template feature was previewed then withdrawn, so formatted / String.format remain the idiomatic approach).

The Java Platform Module System (JPMS) Java 9

A module is a named, self-describing group of packages that declares what it needs (requires) and what it exposes (exports). It adds strong encapsulation and reliable configuration above the old flat classpath.

Why it exists

  • Strong encapsulation — packages not exported are truly hidden, even from reflection.
  • Reliable configuration — missing/duplicate/cyclic dependencies are caught at startup, not deep into a run ("JAR hell").
  • A scalable platform — the JDK itself is ~90 modules, so tools like jlink can ship only what you use.

A module in one file: module-info.java

// src/com.myapp/module-info.java
module com.myapp {
  requires java.net.http;            // I depend on this module
  requires transitive com.mylib;     // and anyone who requires me also gets com.mylib

  exports com.myapp.api;             // this package is public API
  exports com.myapp.internal to com.myapp.tests;   // qualified: only to that module

  uses   com.myapp.spi.Plugin;                     // I consume this service
  provides com.myapp.spi.Plugin
      with com.myapp.plugins.DefaultPlugin;        // I supply an implementation

  opens  com.myapp.model;            // allow deep reflection (e.g. for frameworks)
}

Practical guidance & gotchas

  • You don't have to modularise your app to run on Java 9+. The classpath still works; the "unnamed module" reads everything. Many apps stay on the classpath for years.

Virtual threads Java 21

Virtual threads are extremely lightweight threads scheduled by the JVM, not the OS. They let you write plain blocking, thread-per-request code that scales to millions of concurrent tasks — no callbacks, no reactive plumbing.

The problem they solve

An OS (platform) thread is expensive (~1 MB stack, costly context switches), so you pool a few hundred and never block them carelessly. That forced a choice: simple-but-limited thread-per-request, or scalable-but-complex async/reactive code. Virtual threads remove the choice — block freely, and the JVM parks the virtual thread and reuses the underlying OS thread.

Before — bounded pool, careful blocking
ExecutorService pool = Executors.newFixedThreadPool(200);
for (Request r : requests) {
  pool.submit(() -> {
    var user = db.load(r.userId());   // blocks a precious OS thread
    return render(user);
  });
}
// >200 concurrent requests queue up
After — a thread per task
try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
  for (Request r : requests) {
    ex.submit(() -> {
      var user = db.load(r.userId());  // blocking is cheap now
      return render(user);
    });
  }
}   // millions of concurrent tasks, same simple code

Creating virtual threads

// 1. one-off
Thread t = Thread.ofVirtual().start(() -> work());
t.join();

// 2. a builder / factory
ThreadFactory vf = Thread.ofVirtual().name("worker-", 0).factory();

// 3. an executor (recommended for task fan-out)
try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
  Future<String> f = ex.submit(() -> fetch());
}

// platform (old) thread for comparison:
Thread p = Thread.ofPlatform().start(() -> work());

How they work: carriers & mounting

  • Virtual threads run on a small pool of carrier (platform) threads — by default a ForkJoinPool sized to the CPU count.
  • When a virtual thread hits a blocking call (I/O, sleep, locks), it unmounts from its carrier so the carrier can run another virtual thread. When the blocking call completes, it remounts (possibly on a different carrier).
  • Its stack lives on the heap, so a virtual thread costs bytes, not megabytes.

Rules & gotchas

  • Don't pool virtual threads. They're cheap and disposable — create one per task. Pooling defeats the purpose.
  • Pinning: in Java 21 a virtual thread stayed "pinned" to its carrier while inside a synchronized block or a native call, which could starve the carrier pool. Fixed in 24 — synchronized no longer pins (JEP 491). On 21–23, prefer ReentrantLock over synchronized around blocking I/O.
  • They don't make CPU-bound work faster. The win is for I/O-bound / high-concurrency workloads. CPU-bound work is still limited by cores.
  • ThreadLocal still works but is discouraged at massive scale (per-thread copies add up). Prefer scoped values.
  • Semaphores, not pools, for limiting a scarce downstream resource: 
    Semaphore db = new Semaphore(50);   // cap concurrent DB calls
// inside each virtual thread:
db.acquire(); try { query(); } finally { db.release(); }
Rule of thumb: keep writing straightforward blocking code, run each request/task on its own virtual thread, and use structured concurrency to manage groups of subtasks.

Pairs with

  • Structured concurrency — manage a group of subtasks as one unit.
  • Scoped values — share immutable per-request context safely.

Structured concurrency Preview

Structured concurrency treats a group of related subtasks as a single unit of work. They start together, and the scope guarantees they all finish (or are cancelled) before the block exits — no leaked threads, clear error propagation, honest stack traces.

Still a preview feature (5th preview in Java 25, 6th in 26). Compile/run with --enable-preview. The API shown here is the reworked Java 25 shape; earlier releases used ShutdownOnFailure/ShutdownOnSuccess (see Evolution).

The problem: unstructured concurrency leaks

Before — ExecutorService, manual coordination
Future<User>  u = pool.submit(() -> findUser(id));
Future<Order> o = pool.submit(() -> fetchOrder(id));
try {
  return new Response(u.get(), o.get());
  // if findUser throws, fetchOrder keeps running (leak);
  // cancellation & error handling are all manual and easy to botch
} catch (Exception e) {
  u.cancel(true); o.cancel(true);   // did you remember both?
  throw e;
}
After — one scope, one unit
try (var scope = StructuredTaskScope.open()) {   // Java 25 API
  Subtask<User>  u = scope.fork(() -> findUser(id));
  Subtask<Order> o = scope.fork(() -> fetchOrder(id));

  scope.join();            // wait for all; propagate the first failure,
                           // cancelling the siblings automatically
  return new Response(u.get(), o.get());
}   // on exit, every subtask is guaranteed done

Why it's better

  • No leaks: the try-with-resources block can't exit until all forked subtasks complete or are cancelled.
  • Short-circuiting: if one subtask fails, the others are cancelled — you don't wait on work you'll throw away.
  • Clear hierarchy: subtasks are children of the scope; observability tools show the real task tree.
  • Cheap: each subtask runs on its own virtual thread.

Joiners — choosing the completion policy (Java 25)

A Joiner decides when join() returns and how results/errors combine.

// Fail fast: all must succeed, or the first exception is thrown
try (var scope = StructuredTaskScope.open(Joiner.<String>allSuccessfulOrThrow())) {
  scope.fork(() -> a());
  scope.fork(() -> b());
  var results = scope.join();   // Stream of subtasks, all succeeded
}

// Race: return the first success, cancel the rest
try (var scope = StructuredTaskScope.open(Joiner.<String>anySuccessfulResultOrThrow())) {
  scope.fork(() -> mirror1());
  scope.fork(() -> mirror2());
  String fastest = scope.join();
}

Deadlines & cancellation

try (var scope = StructuredTaskScope.open(
        Joiner.allSuccessfulOrThrow(),
        cf -> cf.withTimeout(Duration.ofSeconds(2)))) {   // whole group deadline
  scope.fork(() -> slowCall());
  scope.join();   // throws if the deadline passes; subtasks cancelled
}

Gotchas

  • Read subtask results only after join(). Calling Subtask.get() before joining throws IllegalStateException.
  • The scope is confined to one thread — fork from the thread that opened it.
  • Preview API is moving. Don't build production infrastructure on the exact method names yet; the concept is stable, the surface is still settling.
  • Pairs naturally with scoped values to pass request context into every subtask immutably.

Scoped values Java 25

A ScopedValue shares immutable data with methods further down the call stack without passing it as a parameter — a modern, safer, virtual-thread-friendly replacement for many uses of ThreadLocal.

Why not just ThreadLocal?

ThreadLocalScopedValue
MutabilityMutable any time (set)Immutable; bound for a scope only
LifetimeUntil removed (leaks if you forget remove())Auto-unbound when the scope block exits
InheritanceCopied to child threads (expensive)Shared by structure, no copying
At scaleCostly with millions of virtual threadsDesigned for it

Before & after

Before — ThreadLocal, mutable, leak-prone
static final ThreadLocal<User> CURRENT = new ThreadLocal<>();

void handle(Request r) {
  CURRENT.set(authenticate(r));
  try {
    process();               // deep code calls CURRENT.get()
  } finally {
    CURRENT.remove();        // MUST remember, or you leak / see stale data
  }
}
After — ScopedValue, immutable, self-cleaning
static final ScopedValue<User> CURRENT = ScopedValue.newInstance();

void handle(Request r) {
  ScopedValue.where(CURRENT, authenticate(r))
             .run(() -> process());   // bound only inside run(...)
}   // automatically unbound here — nothing to clean up

Reading the value

void process() {
  User u = CURRENT.get();          // whatever was bound in the enclosing scope
  if (CURRENT.isBound()) { ... }   // check before get() to avoid an exception
}

Binding: run vs call, and multiple values

// run: no result;  call: returns a value / may throw checked exceptions
String out = ScopedValue.where(CURRENT, user).call(() -> render());

// bind several at once
ScopedValue.where(CURRENT, user)
           .where(TENANT, tenant)
           .run(() -> handle());

// rebind for a narrower scope (does not mutate — shadows within the nested block)
ScopedValue.where(CURRENT, adminUser).run(() -> doPrivileged());

Works across subtasks with structured concurrency

A scoped value bound in a scope is visible to every subtask forked inside it — the clean way to propagate request context to concurrent work.

ScopedValue.where(CURRENT, user).run(() -> {
  try (var scope = StructuredTaskScope.open()) {
    scope.fork(() -> loadProfile());   // sees CURRENT.get() == user
    scope.fork(() -> loadOrders());    // also sees it
    scope.join();
  }
});

Gotchas

  • Immutable by design: there is no set(). To "change" a value for a sub-computation, rebind it in a nested where(...).run(...).
  • get() outside a binding throws — guard with isBound() or provide a default via orElse.
  • Not a global variable. The value exists only during the dynamic extent of the run/call. That's the point — it can't leak.

Stream Gatherers Java 24

A Gatherer is a custom intermediate stream operation — the long-missing counterpart to a custom Collector. Where collect ends a stream, gather transforms it mid-pipeline: windowing, running totals, dedup-by-key, throttling and more.

The gap it fills

Streams shipped with a fixed set of intermediate ops (map, filter, limit…). Anything stateful or many-to-one across elements — sliding windows, "stop after N distinct", running averages — meant dropping out of the stream. Gatherers make those first-class and composable.

Built-in gatherers

import java.util.stream.Gatherers;

// fixed-size batches
Stream.of(1,2,3,4,5).gather(Gatherers.windowFixed(2)).toList();
// [[1,2],[3,4],[5]]

// sliding windows
Stream.of(1,2,3,4).gather(Gatherers.windowSliding(2)).toList();
// [[1,2],[2,3],[3,4]]

// running fold (like reduce but emits each step)
Stream.of(1,2,3,4).gather(Gatherers.scan(() -> 0, Integer::sum)).toList();
// [1,3,6,10]

// stateful fold to a single value, emitted at the end
Stream.of("a","b","c").gather(Gatherers.fold(() -> "", String::concat)).toList();
// ["abc"]

// bounded-parallelism mapping that preserves order
urls.stream().gather(Gatherers.mapConcurrent(10, this::fetch)).toList();

Before & after — sliding windows

Before — manual index loop
List<List<Integer>> windows = new ArrayList<>();
for (int i = 0; i + 3 <= xs.size(); i++) {
  windows.add(List.copyOf(xs.subList(i, i + 3)));
}
// breaks the pipeline; needs a materialised list
After
var windows = xs.stream()
    .gather(Gatherers.windowSliding(3))
    .toList();      // stays lazy & composable

Writing your own gatherer

A gatherer has up to four parts: an initializer (state), an integrator (per element — the core), an optional combiner (for parallel), and an optional finisher.

// "distinct by key" as a gatherer
static <T, K> Gatherer<T, ?, T> distinctBy(Function<T, K> key) {
  return Gatherer.ofSequential(
    HashSet::new,                              // initializer: the seen-keys set
    (seen, item, downstream) -> {              // integrator
      if (seen.add(key.apply(item)))
        return downstream.push(item);          // emit only first per key
      return true;                             // true = keep going
    });
}

// usage
people.stream().gather(distinctBy(Person::city)).toList();

The integrator returns false to short-circuit the upstream (e.g. once you've emitted enough) — that's how a gatherer can implement limit-like behaviour.

  • Order & parallelism: supply a combiner only if your state merges correctly in parallel; otherwise use Gatherer.ofSequential(...).
  • mapConcurrent is the sweet spot for bounded concurrent I/O within a stream — it caps in-flight tasks and preserves encounter order (backed by virtual threads).

Foreign Function & Memory API Java 22

The FFM API lets pure Java call native (C) functions and access off-heap memory safely and without writing any C glue. It's the modern, supported replacement for JNI and the old sun.misc.Unsafe tricks.

Why it replaces JNI

ErgonomicsBoilerplate-heavyFluent method handles + layouts

Two halves of the API

1 · Off-heap memory: Arena & MemorySegment

Before — ByteBuffer / Unsafe
ByteBuffer buf = ByteBuffer.allocateDirect(16)
    .order(ByteOrder.nativeOrder());
buf.putInt(0, 42);
int v = buf.getInt(0);
// no explicit lifetime; freeing is up to the GC/cleaner
After — Arena + MemorySegment
try (Arena arena = Arena.ofConfined()) {
  MemorySegment seg = arena.allocate(ValueLayout.JAVA_INT, 4);
  seg.setAtIndex(ValueLayout.JAVA_INT, 0, 42);
  int v = seg.getAtIndex(ValueLayout.JAVA_INT, 0);
}   // memory released deterministically here

Arena controls lifetime & access: ofConfined() (one thread, cheapest), ofShared() (many threads), ofAuto() (GC-managed), global() (never freed). Access after an arena closes throws instead of corrupting memory.

2 · Calling native functions: Linker & method handles

// call C's  size_t strlen(const char *s);
Linker linker = Linker.nativeLinker();
SymbolLookup std = linker.defaultLookup();

MethodHandle strlen = linker.downcallHandle(
    std.find("strlen").orElseThrow(),
    FunctionDescriptor.of(ValueLayout.JAVA_LONG,      // return: size_t
                          ValueLayout.ADDRESS));      // arg: char*

try (Arena arena = Arena.ofConfined()) {
  MemorySegment cString = arena.allocateUtf8String("hello");
  long len = (long) strlen.invoke(cString);           // -> 5
}

Upcalls — pass a Java method as a C callback

// turn a Java method into a native function pointer (e.g. for qsort's comparator)
MethodHandle cmp = MethodHandles.lookup().findStatic(
    MyCmp.class, "compare",
    MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class));
MemorySegment cmpPtr = linker.upcallStub(cmp,
    FunctionDescriptor.of(JAVA_INT, ADDRESS, ADDRESS), arena);

jextract — generate bindings automatically

For real libraries you rarely hand-write handles. The jextract tool reads a C header and generates ready-to-use Java bindings:

jextract --output src -t org.example.zlib \
    -l z /usr/include/zlib.h
// then call generated methods like zlib.compress(...)

Gotchas

  • Native access is restricted. Since integrity work, calling native code may require --enable-native-access=<module> (or ALL-UNNAMED) or you'll get warnings/errors.
  • Confined arenas are single-thread. Sharing a confined segment across threads throws — use ofShared().
  • Layouts must match the C ABI exactly (sizes, alignment, endianness). Mismatches corrupt data — prefer jextract.
  • Off-heap memory isn't GC'd on the heap — the Arena is your allocation lifetime. Use try-with-resources.
