Pattern matching & switch

Java grew a family of related features that let you test a type, bind a variable, and destructure data in one step — turning long if/instanceof/cast chains and fall-through switch statements into concise, exhaustive expressions.

The pieces, and when each arrived

FeatureFinalWhat it does

Pattern matching for instanceof16Test + cast + bind in one.

1 · Switch expressions Java 14

Before — statement, break, fall-through bugs
int num;
switch (day) {
  case MON: case TUE: case WED:
  case THU: case FRI:
    num = 5; break;
  case SAT: case SUN:
    num = 2; break;
  default:
    throw new IllegalStateException();
}
After
int num = switch (day) {
  case MON, TUE, WED, THU, FRI -> 5;
  case SAT, SUN                -> 2;
};   // arrow = no fall-through; exhaustive on enums

// block form uses yield:
int n = switch (day) {
  case MON -> { log(day); yield 5; }
  default  -> 0;
};

2 · Pattern matching for instanceof Java 16

Before
if (o instanceof String) {
  String s = (String) o;    // repeat + cast
  if (s.length() > 3) ...
}
After
if (o instanceof String s && s.length() > 3) {
  ...   // s is in scope where the test is true
}

The bound variable's scope follows control flow ("flow scoping"): it's available exactly where the pattern is known to have matched — including after an early return:

if (!(o instanceof String s)) return;
// s is in scope here, because we only get past the guard when it matched
System.out.println(s.length());

3 · Pattern matching for switch Java 21

String describe(Object o) {
  return switch (o) {
    case null            -> "null";                 // null can be a case
    case Integer i when i < 0 -> "negative int";    // guarded pattern
    case Integer i       -> "int " + i;
    case String s        -> "string of " + s.length();
    case int[] arr       -> "array len " + arr.length;
    default              -> "something else";
  };
}
  • Guards use when. Order matters — the first matching label wins.
  • null handling: add case null to handle it (otherwise a null selector throws NullPointerException, as before).
  • Exhaustiveness: over a sealed type or enum, the compiler verifies all cases are covered — no default needed. See Sealed classes.

4 · Record patterns Java 21

Destructure a record's components directly, nesting arbitrarily deep.

Before
if (obj instanceof Line l) {
  Point a = l.start(), b = l.end();
  int x1 = a.x(), y1 = a.y();
  int x2 = b.x(), y2 = b.y();
  ...
}
After
if (obj instanceof Line(Point(var x1, var y1),
                        Point(var x2, var y2))) {
  ...   // all four bound at once
}
// combine with switch for clean recursive code
sealed interface Expr permits Num, Add {}
record Num(int v) implements Expr {}
record Add(Expr l, Expr r) implements Expr {}

int eval(Expr e) {
  return switch (e) {
    case Num(int v)          -> v;
    case Add(Expr l, Expr r) -> eval(l) + eval(r);
  };   // exhaustive, no default
}

5 · Unnamed patterns & variables _ Java 25

if (obj instanceof Point(int x, _)) use(x);      // ignore y
switch (shape) {
  case Circle(var r)           -> ...;
  case Rectangle(var w, _)     -> ...;            // ignore height
}
catch (NumberFormatException _) { retry(); }      // ignore the exception object
for (var _ : items) count++;                      // ignore the element

6 · Primitive type patterns Preview

Extends patterns to primitives with safe exactness checks (still preview through Java 26).

switch (obj) {
  case int i    -> ...;
  case double d -> ...;
}
if (longValue instanceof int i) { ... }   // matches only if it fits exactly in int

Gotchas

  • Dominance: a broader pattern can't precede a narrower one — the compiler rejects unreachable cases (put case Integer i when … before the plain case Integer i).
  • null: only matched if you write case null (or case null, default); otherwise NPE on a null selector.
  • Guards vs. patterns: exhaustiveness ignores when guards — a guarded case never counts toward covering all subtypes.

Cheat card

  • switch (x) { case A a -> ...; } — value-returning, no fall-through.
  • if (o instanceof String s) — test + bind, flow-scoped.
  • case Foo f when cond -> — guarded pattern.
  • case Point(var x, var y) -> — record destructuring, nestable.
  • _ ignores a binding; case null handles null.
  • Sealed/enum selector ⇒ exhaustive, no default.
