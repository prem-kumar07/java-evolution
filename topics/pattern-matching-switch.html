Pattern matching & switch

A family of related features that let you test a type, bind a variable and destructure data in one step — turning long if / instanceof / cast chains and fall-through switch statements into concise, exhaustive, readable expressions.

3-in-1test + cast + bind

14→25built up over releases
Java 21switch patterns final
The problem it solves Working with a value whose concrete type varies used to mean a ladder of if (x instanceof T) + cast + extract, or a switch riddled with break and fall-through bugs. Pattern matching makes "what is this, and pull it apart" a first-class, compiler-checked operation — the basis of data-oriented programming in Java.

2 · Switch expressions Java 14

Legacy — statement, break, fall-through
int num;
switch (day) {
  case MON: case TUE: case WED:
  case THU: case FRI:
    num = 5; break;          // forget break → bug
  case SAT: case SUN:
    num = 2; break;
  default:
    throw new IllegalStateException();
}
Switch expression
int num = switch (day) {
  case MON, TUE, WED, THU, FRI -> 5;
  case SAT, SUN                -> 2;
};   // arrow: no fall-through; exhaustive over the enum

// block form uses yield:
int n = switch (day) {
  case MON -> { log(day); yield 5; }
  default  -> 0;
};

3 · Pattern matching for instanceof Java 16

Legacy
if (o instanceof String) {
  String s = (String) o;      // repeat the type + cast
  if (s.length() > 3) use(s);
}
Pattern
if (o instanceof String s && s.length() > 3) {
  use(s);                     // s bound where the test is true
}

Flow scoping: the binding is in scope exactly where the pattern is known to have matched — including after an early return:

if (!(o instanceof String s)) return;
// we only reach here if it matched, so s is in scope:
System.out.println(s.length());

4 · Pattern matching for switch + guards Java 21

Legacy — instanceof ladder
String describe;
if (o instanceof Integer i && i < 0) describe = "negative";
else if (o instanceof Integer i)     describe = "int " + i;
else if (o instanceof String s)      describe = "str " + s;
else if (o == null)                  describe = "null";
else                                 describe = "other";
Switch with patterns + guards
String describe = switch (o) {
  case null                   -> "null";      // null is a case
  case Integer i when i < 0    -> "negative";  // guard with 'when'
  case Integer i              -> "int " + i;
  case String s               -> "str " + s;
  default                     -> "other";
};
  • Guards use when. The first matching label wins, so order matters.
  • null only matches if you add case null (or case null, default); otherwise a null selector throws NPE, as before.
  • Over a sealed type or enum the switch is exhaustive — no default needed.

5 · Record patterns (destructuring) Java 21

Legacy — manual extraction
if (obj instanceof Line l) {
  Point a = l.start(), b = l.end();
  int x1 = a.x(), y1 = a.y();
  int x2 = b.x(), y2 = b.y();
}
Record pattern (nested)
if (obj instanceof Line(Point(var x1, var y1),
                        Point(var x2, var y2))) {
  // x1,y1,x2,y2 all bound
}
// recursion over an expression tree becomes trivial
sealed interface Expr permits Num, Add {}
record Num(int v) implements Expr {}
record Add(Expr l, Expr r) implements Expr {}

int eval(Expr e) {
  return switch (e) {
    case Num(int v)          -> v;
    case Add(Expr l, Expr r) -> eval(l) + eval(r);
  };   // exhaustive, no default
}

6 · Unnamed patterns & variables _ Java 22

if (obj instanceof Point(int x, _)) use(x);       // ignore y
switch (shape) {
  case Rectangle(var w, _) -> useWidth(w);         // ignore height
}
catch (NumberFormatException _) { retry(); }        // ignore the exception object
for (var _ : items) count++;                         // ignore the element

switch (obj) {
  case int i    -> handleInt(i);
  case double d -> handleDouble(d);
  default       -> {}
}
if (longValue instanceof int i) { ... }   // matches only if it fits exactly in int

8 · Dominance & exhaustiveness

  • Dominance: a broader pattern can't precede a narrower one — the compiler rejects the unreachable case. Put case Integer i when … before the plain case Integer i.
  • Exhaustiveness: over a sealed type/enum the compiler verifies all cases are covered. Guarded (when) cases don't count toward covering a subtype, so keep an unguarded fallback for that type.
  • Null: add case null to handle null in-switch instead of guarding before.

9 · Pitfalls

PitfallReality
Case orderFirst match wins; guarded/narrower cases must precede broader ones or you get "dominated"/unreachable errors.
NullNot matched unless case null is present — otherwise NPE on a null selector.
Guards & exhaustivenessA when guard never satisfies exhaustiveness for its type.
Mixing arrow & colon labelsNot allowed in the same switch — pick one style.
Over-nesting record patternsDeep destructuring can hurt readability — bind an intermediate where clearer.

Worked example — render a JSON value

Legacy — instanceof + casts + manual recursion
String render(Object json) {
  if (json instanceof Map) {
    Map<?,?> m = (Map<?,?>) json;
    StringBuilder sb = new StringBuilder("{");
    for (var e : m.entrySet())
      sb.append(e.getKey()).append(":")
        .append(render(e.getValue())).append(",");
    return sb.append("}").toString();
  } else if (json instanceof List) {
    ...
  } else if (json instanceof String s) {
    return "\"" + s + "\"";
  }
  return String.valueOf(json);
}
Sealed model + switch patterns
sealed interface Json permits JObj, JArr, JStr, JNum {}
record JObj(Map<String,Json> fields) implements Json {}
record JArr(List<Json> items)        implements Json {}
record JStr(String value)            implements Json {}
record JNum(double value)            implements Json {}

String render(Json j) {
  return switch (j) {
    case JStr(var s)  -> "\"" + s + "\"";
    case JNum(var n)  -> String.valueOf(n);
    case JArr(var xs) -> xs.stream().map(this::render)
                           .collect(joining(",", "[", "]"));
    case JObj(var m)  -> m.entrySet().stream()
        .map(e -> "\"" + e.getKey() + "\":" + render(e.getValue()))
        .collect(joining(",", "{", "}"));
  };   // exhaustive — a new Json variant forces an update here
}

11 · Cheat sheet

Pattern matching in one glance

  • switch (x) { case A a -> …; } — value-returning, no fall-through.
  • if (o instanceof String s) — test + bind, flow-scoped.
  • case Foo f when cond -> — guarded pattern.
  • case Point(var x, var y) -> — record destructuring, nestable.
  • _ ignores a binding; case null handles null.
  • Sealed/enum selector ⇒ exhaustive, no default; order narrow→broad.
