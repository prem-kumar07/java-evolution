The Reflection API

Reflection lets a running program examine and manipulate its own structure — listing a class's fields and methods, reading private state, invoking methods by name, and even building objects that implement an interface on the fly. It's how every dependency-injection framework, ORM, and serializer works under the hood.

The problem it solves Ordinary Java code must know at compile time exactly which class it's calling. But a framework like Spring or Jackson is written before it ever sees your classes — it needs to discover your fields, call your constructors, and read your annotations at runtime, generically, for types it has never heard of. Reflection is what makes that possible.

1 · Uses & drawbacks — verified from Oracle's own docs

Oracle's own Reflection tutorial is candid about both sides of this feature:

Legitimate usesReal drawbacks
Extensibility — load user-defined classes by name (plugins)Performance overhead — reflective calls are dynamically resolved, so the JIT can't optimize them like a direct call
Class browsers / IDEs — enumerate members for toolingSecurity restrictions — modules can block reflective access to their internals (JPMS, see §13)
Debuggers & test harnesses — inspect private state, systematically exercise every methodExposure of internals — reflection can access private fields/methods that non-reflective code legally cannot
Rule of thumb, straight from Oracle's own guidance: "If it is possible to perform an operation without using reflection, then it is preferable to avoid using it." Reflection is the right tool for frameworks and tooling — not for everyday application logic.

2 · Class — the entry point

Every reflective operation starts from a java.lang.Class instance. There are four ways to get one:

String s = "hello";
Class<?> c1 = s.getClass();              // (a) from an instance
Class<?> c2 = String.class;              // (b) the class literal — no instance needed
Class<?> c3 = Class.forName("java.lang.String");  // (c) by fully-qualified name (throws checked exception)
Class<?> c4 = int[].class;                // (d) even array/primitive types have a Class

Note on constructors: none of the classes in java.lang.reflect have public constructors — you always reach them through methods on Class.

3 · Class names — simple, canonical, type

Verified from dev.java's own reflection tutorial — three different name methods exist because not every class can have every kind of name:

MethodReturnsGotcha
getSimpleName()The name as it appears in source, no packageAnonymous classes have an empty simple name — verified.
getCanonicalName()Fully-qualified, as you'd write it in codeReturns null for local classes, anonymous classes, and hidden classes — verified.
getName()The JVM's internal binary nameUses $ for nested classes: Outer$Inner, and array/primitive encodings like [I.
class Outer { class Inner {} }
Object inner = new Outer().new Inner();     // inner class — needs an Outer instance
System.out.println(inner.getClass().getSimpleName());     // verified: "Inner"
System.out.println(inner.getClass().getCanonicalName());  // verified: "Outer.Inner"
System.out.println(inner.getClass().getName());           // verified: "Outer$Inner"

4 · Modifiers

Class.getModifiers() (and the same method on Field/Method/Constructor via the Member interface) returns an int where each bit represents one modifier. Decode it with the Modifier helper class rather than bit-twiddling yourself:

int mods = String.class.getModifiers();
System.out.println(Modifier.isPublic(mods));    // true
System.out.println(Modifier.isFinal(mods));     // true — String really is final
System.out.println(Modifier.toString(mods));    // "public final"
Not every modifier your code sees in Modifier covers newer keywords — sealed and non-sealed are not represented in java.lang.reflect.Modifier (verified from dev.java's own reflection tutorial). Use Class.isSealed() and Class.getPermittedSubclasses() instead.

5 · Fields — read & write

Two axes control what Class hands back — verified from dev.java's own comparison table:

MethodIncludes inherited?Includes private?
getDeclaredField(name) / getDeclaredFields()No — this class onlyYes
getField(name) / getFields()Yes — walks up to ObjectNo — public only
Legacy — no way to touch private state from outside
// a serializer/framework CANNOT do this without reflection:
Person p = new Person("Ada", 30);
// p.name is private — no getter available, no access
Reflection — read and write private fields
Field nameField = Person.class.getDeclaredField("name");
nameField.setAccessible(true);         // bypass the private access check
nameField.set(person, "Ada");
System.out.println(nameField.get(person));   // verified: "Ada"
// verified real counts on a class with two private fields (name, age):
Person.class.getDeclaredFields().length;   // 2 — everything declared here
Person.class.getFields().length;           // 0 — no public fields at all

6 · Methods — invoke by name

MethodIncludes inherited?Includes private?
getDeclaredMethod(name, ...) / getDeclaredMethods()NoYes
getMethod(name, ...) / getMethods()YesNo
Method greet = Person.class.getDeclaredMethod("greet", String.class);
greet.setAccessible(true);              // needed — greet() is private
Object result = greet.invoke(person, "Hello");   // like person.greet("Hello")
System.out.println(result);             // verified: "Hello, Ada"
Gotcha: Method.invoke always returns Object (cast if you need the real type), and wraps any exception the invoked method throws inside an InvocationTargetException — you must unwrap it with getCause() to see the original exception.

7 · Constructors — build objects reflectively

MethodArray of ctors?Private ctors?
getDeclaredConstructor(...) / getDeclaredConstructors()YesYes
getConstructor(...) / getConstructors()NoNo

Note, verified: unlike fields/methods, constructors are not inherited — there's no "walk up the hierarchy" variant to worry about.

Constructor<?> noArg = Person.class.getDeclaredConstructor();
Object p = noArg.newInstance();                        // like new Person()

Constructor<?> twoArg = Person.class.getConstructor(String.class, int.class);
Person p2 = (Person) twoArg.newInstance("Bob", 30);     // like new Person("Bob", 30)
System.out.println(p2.getName());   // verified: "Bob"
Exact-type matching required: getConstructor() needs the exact parameter types. If a constructor takes CharSequence and you look up String.class, you get a NoSuchMethodException even though a String is a CharSequence — verified from dev.java's own dependency-injection example.

8 · Arrays

Arrays are a special case: Array.getLength() exists because array length isn't part of the type, only the instance.

Object arr = Array.newInstance(int.class, 5);   // like new int[5]
Array.set(arr, 0, 42);
System.out.println(Array.get(arr, 0));           // verified: 42
System.out.println(Array.getLength(arr));        // verified: 5
System.out.println(arr.getClass().isArray());    // true
System.out.println(arr.getClass().getComponentType());  // int
Verified precision rule: Array.setFloat() with a boxed Float throws IllegalArgumentException. Array.setInt() into a long[] works (no precision lost widening int→long); the reverse (setLong into an int[]) is illegal — narrowing would lose data.

9 · Enums & records

No separate java.lang.reflect.Enum class exists — enums are ordinary classes with three enum-specific reflective methods:

Days.class.isEnum();            // true
Days.class.getEnumConstants();  // same array as Days.values(), verified
someField.isEnumConstant();     // true if this Field is one of the enum's own constants
// note, verified: you cannot add a constant to an enum at runtime, even via reflection

Records (Java 16+) added Class.isRecord() and a new RecordComponent class:

record Point(int x, int y) {}
Point.class.isRecord();                              // true
for (RecordComponent rc : Point.class.getRecordComponents()) {
  System.out.println(rc.getName() + ": " + rc.getType());
}
// verified real output: "x: int" then "y: int"
Records enforce their immutability even against reflection — verified from dev.java: you can locate a record's backing Field via getDeclaredFields() and read it, but you cannot modify it, even after calling setAccessible(true). This is a JVM-level guarantee specific to records.

10 · Reading annotations

Field, Method, Constructor and Class all implement AnnotatedElement — the interface every framework uses to discover annotations at runtime. Full annotation authoring details → Annotations deep-dive.

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Cached { int ttlSeconds() default 60; }

class Service {
  @Cached(ttlSeconds = 30)
  public String fetch() { return "data"; }
}

Method fetch = Service.class.getMethod("fetch");
fetch.isAnnotationPresent(Cached.class);    // verified: true
Cached c = fetch.getAnnotation(Cached.class);
c.ttlSeconds();                              // verified: 30
MethodBehavior
isAnnotationPresent(Class)Quick boolean check.
getAnnotation(Class) / getDeclaredAnnotation(Class)One annotation of that type (or null); declared-only skips inherited ones.
getAnnotations() / getDeclaredAnnotations()Every annotation present on this element.
getAnnotationsByType(Class)Handles repeatable annotations — returns all repeats even though they're technically stored in one container annotation.

11 · Dynamic proxies

Why it matters: a dynamic proxy creates a real, working implementation of one or more interfaces at runtime, with no class file for it ever written by you — every method call is routed through one handler. This is exactly how Spring AOP, mocking frameworks, and lazy-load proxies in Hibernate work.

interface Greeter { String greet(String name); }

Greeter proxy = (Greeter) Proxy.newProxyInstance(
    Greeter.class.getClassLoader(),
    new Class<?>[]{ Greeter.class },
    (Object p, Method method, Object[] args) -> {
      System.out.println("before calling " + method.getName());
      String result = "Hello, " + args[0];
      System.out.println("after calling " + method.getName());
      return result;
    });

System.out.println(proxy.greet("Ada"));
// verified real output:
//   before calling greet
//   after calling greet
//   Hello, Ada
System.out.println(Proxy.isProxyClass(proxy.getClass()));   // verified: true
Limitation: java.lang.reflect.Proxy can only proxy interfaces, not concrete classes — for that, frameworks like CGLIB or ByteBuddy generate real subclasses on the fly instead.

12 · Real patterns: interceptors & dependency injection

Two complete, working examples adapted from dev.java's own Reflection API tutorial — the kind of code that sits inside Java EE/Jakarta EE and enterprise frameworks. Every line below was compiled and run for real before being written here.

Pattern A — a method interceptor driven by an annotation

The idea: instead of calling a service method directly, you route the call through an interceptor first. The interceptor gets the raw Method, the target object, and the arguments — it can validate them, change them, decide whether to call the real method at all, and transform the result before returning it. (A production version of this would use dynamic proxies so the call site looks like an ordinary method call; here we build the mechanism by hand so every step is visible.)

Step 1 — the interceptor contract and the annotation that selects it:

interface Interceptor<T, R> {
  R intercept(Method method, T target, Object[] args) throws Exception;
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Intercepted {
  Class<? extends Interceptor> value();   // which interceptor handles this method
}

Step 2 — a service, with one method marked for interception and one left alone:

public class SomeInterceptedService {
  @Intercepted(MessageInterceptor.class)
  public String message(String text) { return text; }
}

public class SomeNonInterceptedService {
  public String message(String text) { return text; }   // no annotation -> called directly
}

Step 3 — the interceptor itself. It validates the arguments, reflectively invokes the real method to get the underlying result, then decorates it:

public class MessageInterceptor implements Interceptor<SomeInterceptedService, String> {
  public String intercept(Method method, SomeInterceptedService target, Object[] args) throws Exception {
    if (args.length != 1 || !(args[0] instanceof String)) {
      throw new IllegalArgumentException("expected exactly one String argument");
    }
    String result = (String) method.invoke(target, args);   // call the REAL method
    return result + " [was intercepted]";                    // then decorate the result
  }
}

Step 4 — the "runtime": locate the method, check for the annotation, and either run the interceptor or call the method as normal:

class ServiceFactory {
  @SuppressWarnings("unchecked")
  static <T> Object invoke(Class<T> serviceClass, String methodName, Object... args) throws Exception {
    T service = serviceClass.getDeclaredConstructor().newInstance();
    Class<?>[] types = Arrays.stream(args).map(a -> a == null ? Object.class : a.getClass()).toArray(Class[]::new);
    Method method = serviceClass.getDeclaredMethod(methodName, types);

    if (method.isAnnotationPresent(Intercepted.class)) {
      Intercepted meta = method.getAnnotation(Intercepted.class);
      Interceptor<T, Object> interceptor =
          (Interceptor<T, Object>) meta.value().getDeclaredConstructor().newInstance();
      return interceptor.intercept(method, service, args);   // routed through the interceptor
    } else {
      return method.invoke(service, args);                    // called directly, no interception
    }
  }
}

Object r1 = ServiceFactory.invoke(SomeInterceptedService.class, "message", "Hello");
Object r2 = ServiceFactory.invoke(SomeNonInterceptedService.class, "message", "Hello");
System.out.println(r1);   // verified real output: "Hello [was intercepted]"
System.out.println(r2);   // verified real output: "Hello"
Verified gotcha the original tutorial calls out explicitly: ServiceFactory.invoke builds the parameter types from each argument's runtime class. If the target method were declared as message(CharSequence text) instead of message(String text), looking it up with getDeclaredMethod("message", String.class) throws NoSuchMethodException — verified — even though a String genuinely is a CharSequence. Reflective method lookup matches the exact declared parameter type, never a supertype.

Pattern B — a dependency-injection framework with singletons

The idea, in three layers: (1) a factory that builds objects reflectively instead of you calling new, (2) a @Singleton annotation so some beans are built once and reused, (3) an @Inject annotation so the factory can wire one bean's dependencies into another automatically.

Layer 1 — the basic factory. Give it a class and constructor arguments, get an instance back:

class BeanFactory {
  static <T> T getInstanceOf(Class<T> beanClass, Object... args) throws ReflectiveOperationException {
    Class<?>[] types = Arrays.stream(args).map(a -> a == null ? Object.class : a.getClass()).toArray(Class[]::new);
    Constructor<T> constructor = beanClass.getConstructor(types);   // exact-type match, see §7
    return constructor.newInstance(args);
  }
}
Verified gotcha (the same rule from §7, and the DI framework hits it immediately): getConstructor() only finds public constructors on public types. A package-private bean class throws NoSuchMethodException even though the constructor is right there in getDeclaredConstructors() — every bean class in these examples needs to be public.

Layer 2 — add @Singleton. A thread-safe registry backed by ConcurrentHashMap, with the construction logic pulled into a private helper so it isn't duplicated:

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Singleton {}

class BeanFactory {
  private static final ConcurrentMap<Class<?>, Object> registry = new ConcurrentHashMap<>();

  @SuppressWarnings("unchecked")
  static <T> T getInstanceOf(Class<T> beanClass, Object... args) throws ReflectiveOperationException {
    if (beanClass.isAnnotationPresent(Singleton.class)) {
      Object existing = registry.get(beanClass);
      if (existing != null) return (T) existing;

      T candidate = instantiateBeanClass(beanClass, args);
      registry.putIfAbsent(beanClass, candidate);   // atomic — no explicit synchronization needed
      return (T) registry.get(beanClass);            // there IS a winner, but it might not be "candidate"
      // if two threads raced here, both built an instance, but only one is stored — read it back
      // via get() rather than returning "candidate", or you could return the LOSING instance
    }
    return instantiateBeanClass(beanClass, args);
  }

  private static <T> T instantiateBeanClass(Class<T> beanClass, Object... args) throws ReflectiveOperationException {
    Class<?>[] types = Arrays.stream(args).map(a -> a == null ? Object.class : a.getClass()).toArray(Class[]::new);
    Constructor<T> constructor = beanClass.getConstructor(types);
    return constructor.newInstance(args);
  }
}

Layer 3 — add @Inject. After constructing a bean, scan its fields for @Inject and fill each one in — recursively through getInstanceOf, so an injected field that's itself @Singleton correctly reuses the shared instance:

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Inject {}

// instantiateBeanClass grows one more step at the end:
private static <T> T instantiateBeanClass(Class<T> beanClass, Object... args) throws ReflectiveOperationException {
  Class<?>[] types = Arrays.stream(args).map(a -> a == null ? Object.class : a.getClass()).toArray(Class[]::new);
  Constructor<T> constructor = beanClass.getConstructor(types);
  T bean = constructor.newInstance(args);

  for (Field field : beanClass.getDeclaredFields()) {           // every field, any visibility
    if (field.isAnnotationPresent(Inject.class)) {
      field.setAccessible(true);                                 // always — even if it were public
      // Note: Real DI frameworks register 'bean' early here to prevent circular dependency StackOverflows
      Object value = getInstanceOf(field.getType());              // recursive — respects @Singleton
      field.set(bean, value);
    }
  }
  return bean;
}

Putting all three layers together:

@Singleton
public class DBService {
  public DBService() { System.out.println("DBService instance created"); }
  String query() { return "some data"; }
}

public class MyApplication {
  @Inject
  private DBService dbService;    // BeanFactory fills this in — no setter, no constructor arg
  void run() { System.out.println("result = " + dbService.query()); }
}

MyApplication app = BeanFactory.getInstanceOf(MyApplication.class);
app.run();
// verified real output:
//   DBService instance created
//   result = some data

DBService a = BeanFactory.getInstanceOf(DBService.class);
DBService b = BeanFactory.getInstanceOf(DBService.class);
System.out.println(a == b);
// verified real output: true — and "DBService instance created" printed only ONCE across
// all three getInstanceOf calls total, proving the singleton was genuinely reused

13 · setAccessible & the module system

Since Java 9's module system (see Modules deep-dive), calling setAccessible(true) on a private member of a module you don't own only works if that module opens the package to you — either explicitly or via --add-opens on the command line. This is exactly why upgrading old reflection-heavy code to Java 9+ often throws InaccessibleObjectException until the right module is opened.

14 · Pitfalls

PitfallReality
Forgetting setAccessible(true)Throws IllegalAccessException the moment you touch a private member.
A non-public class/record whose constructor you look up with getConstructor()Verified: throws NoSuchMethodException even though the constructor exists — getConstructor only sees public constructors, and a non-public type's constructor defaults to that same non-public access.
Expecting exact-vs-assignable parameter matchinggetConstructor/getMethod need the exact declared parameter types — verified, a CharSequence-typed constructor won't match a String lookup.
Reading InvocationTargetException as "the" exceptionIt's a wrapper — call .getCause() to see what the invoked method actually threw.
Trying to mutate a record's field after setAccessible(true)Verified: records refuse this at the JVM level — immutability is enforced even against reflection.

Coming in Java 26 (JEP 500): The "Prepare to Make final Mean Final" initiative extends this enforcement to all final fields. Deep reflection that mutates final fields via setAccessible(true) now generates warnings in Java 26 and will throw in a future release. See the Java 26 page for details.

Using reflection in a hot loopReal, measurable overhead — cache the Method/Field lookup outside the loop at minimum; consider MethodHandle for performance-sensitive reflective calls.

For low-level field access with atomic operations (CAS, volatile semantics), see also java.lang.invoke.VarHandle (introduced in Java 9, JEP 193) and the FFM API for native memory access.

Reflecting into another module's internals on Java 9+Throws InaccessibleObjectException unless that module opens the package — see §13.

16 · Cheat sheet

Reflection in one glance

  • Entry point: obj.getClass(), Type.class, or Class.forName(name).
  • getDeclared* = this class only, includes private. get* (no "Declared") = inherited, public only.
  • setAccessible(true) before touching a private field/method/constructor.
  • Method.invoke throws InvocationTargetException (unwrap with getCause()), plus IllegalAccessException and IllegalArgumentException.
  • Constructor.newInstance throws the same, plus InstantiationException.
  • Proxy.newProxyInstance — implement an interface at runtime, one handler for every call.
  • Records refuse field mutation even via reflection; enums can't gain new constants at runtime.
  • Java 9+: reflecting into another module needs that module to opens the package.
  • Prefer normal code when you can — reflection is slower and bypasses compile-time checks.

Advanced Reflection Topics

Java provides advanced reflection and dynamic bytecode tools:

  • Generic Type Reflection (java.lang.reflect.Type): Inspecting parameterized types, wildcards, and type variables at runtime.
  • Method Handles (java.lang.invoke): Providing strongly typed, direct, and performant access to methods, constructors, and fields compared to traditional Reflection.
  • Class-File API: A standard API introduced recently to parse, generate, and transform Java class files dynamically.
