Java Flight Recorder (JFR) & JMC Java 11

Java Flight Recorder (JFR) is an event-driven diagnostic and profiling framework built directly into the HotSpot JVM. It captures low-level JVM internals (GC, threads, memory, CPU) with negligible runtime overhead (< 1–2%), making it the standard for production profiling.

The problem it solves Profiling Java applications in production historically required attaching heavyweight agents that skewed performance metrics and slowed down the application. JFR is deeply embedded into the JVM, allowing continuous, always-on "black box" flight recording without impacting user latencies.

1 · Starting Recordings

You can start JFR at launch using JVM flags, or dynamically at runtime using the jcmd CLI.

Via JVM Flags

# Start a continuous recording with a rolling 1-hour buffer
$ java -XX:StartFlightRecording=disk=true,maxage=1h,settings=default -jar app.jar

# Start a highly detailed 60-second profile
$ java -XX:StartFlightRecording=filename=startup.jfr,duration=60s,settings=profile -jar app.jar

Via jcmd (Dynamically)

Find your Java PID using jcmd -l, then issue commands to the running JVM:

# Start recording
$ jcmd <PID> JFR.start name=ProdTrace settings=profile duration=60s filename=/tmp/prod.jfr

# Dump active recording without stopping it
$ jcmd <PID> JFR.dump name=ProdTrace filename=/tmp/snapshot.jfr

# Stop recording
$ jcmd <PID> JFR.stop name=ProdTrace

2 · JDK Mission Control (JMC)

JDK Mission Control (JMC) is the official desktop GUI for analyzing .jfr dump files. It provides:

  • Automated Analysis: Rule-based scorecard with tuning recommendations (e.g., GC pauses, memory leaks).
  • Flame Graphs: Visualizes call trees and hotspot methods.
  • Thread & Lock Contention: Swimlanes for thread states, lock wait times, and deadlocks.
  • Memory Profiling: Allocation pressure, object lifetimes, and heap fragmentation.

3 · Custom Application Events

You can emit your own application telemetry directly into the JFR pipeline alongside JVM events.

import jdk.jfr.*;

@Name("com.example.OrderProcessed")
@Label("Order Processed")
@Category({"E-Commerce", "Orders"})
public class OrderEvent extends Event {
    @Label("Order ID")
    String orderId;

    @Label("Amount")
    double amount;
}

// Usage in application code
public void processOrder(String id, double amt) {
    OrderEvent event = new OrderEvent();
    event.begin();
    try {
        // ... business logic ...
    } finally {
        event.orderId = id;
        event.amount = amt;
        event.end();
        event.commit(); // Writes to the JFR buffer
    }
}

4 · JFR Event Streaming Java 14

Introduced in Java 14 (JEP 349), Event Streaming allows applications to consume JFR events continuously in real-time, completely bypassing the need to dump .jfr files to disk.

import jdk.jfr.consumer.RecordingStream;
import java.time.Duration;

public class JfrStreamer {
    public static void main(String[] args) throws Exception {
        try (var stream = new RecordingStream()) {
            
            // Sample built-in CPU load every 1 second
            stream.enable("jdk.CPULoad").withPeriod(Duration.ofSeconds(1));
            
            stream.onEvent("jdk.CPULoad", event -> {
                float machineCpu = event.getFloat("machineTotal") * 100;
                float jvmCpu = event.getFloat("jvmUser") * 100;
                System.out.printf("CPU - Machine: %.1f%% | JVM: %.1f%%%n", machineCpu, jvmCpu);
            });

            // Listen to your custom application events instantly
            stream.onEvent("com.example.OrderProcessed", event -> {
                System.out.println("Order completed: $" + event.getDouble("amount"));
            });

            // Start asynchronously
            stream.startAsync();
            
            // Keep app alive
            Thread.sleep(Long.MAX_VALUE);
        }
    }
}
