Scoped values Final in Java 25

A ScopedValue shares immutable data with code further down the call stack without passing it as a parameter — a modern, safer, virtual-thread-friendly replacement for many uses of ThreadLocal.

The problem it solves ThreadLocal is mutable (anyone can set() it any time), leaks unless you remember remove(), and is copied into every child thread — painful with millions of virtual threads. Scoped values give you the same "ambient context" without those hazards: bound for a well-defined scope, immutable, and cleaned up automatically.

1 · Why not ThreadLocal?

ThreadLocalScopedValue
MutabilityMutable any time (set)Immutable; bound for a scope only
LifetimeUntil remove() (leaks if forgotten)Auto-unbound when the block exits
InheritanceCopied into child threads (costly)Shared by structure, no copy
At VT scaleExpensive with millions of threadsDesigned for it
Reasoning"Who set this, and is it stale?"Value is fixed for the dynamic extent
Legacy — ThreadLocal, mutable, must clean up
static final ThreadLocal<User> CURRENT = new ThreadLocal<>();

void handle(Request r) {
  CURRENT.set(authenticate(r));
  try {
    process();               // deep code calls CURRENT.get()
  } finally {
    CURRENT.remove();        // MUST remember or you leak / see stale data
  }
}
ScopedValue — immutable, self-cleaning
static final ScopedValue<User> CURRENT = ScopedValue.newInstance();

void handle(Request r) {
  ScopedValue.where(CURRENT, authenticate(r))
             .run(() -> process());   // bound only inside run(...)
}   // automatically unbound here — nothing to clean up

2 · Declare, bind, read

// declare once (shared, final)
static final ScopedValue<User> CURRENT = ScopedValue.newInstance();

// bind for a scope
ScopedValue.where(CURRENT, user).run(() -> process());

// read anywhere inside that scope
void process() {
  User u = CURRENT.get();          // the value bound above
  if (CURRENT.isBound()) { ... }   // guard before get() to avoid an exception
}

4 · run / call / multiple / rebinding

// run: no result;  call: returns a value / may throw checked exceptions
String out = ScopedValue.where(CURRENT, user).call(() -> render());

// bind several at once
ScopedValue.where(CURRENT, user)
           .where(TENANT, tenant)
           .run(() -> handle());

// rebinding = a nested, narrower scope (does NOT mutate — it shadows)
ScopedValue.where(CURRENT, adminUser).run(() -> doPrivileged());

// provide a fallback instead of throwing when unbound
User u = CURRENT.orElse(GUEST);

5 · With structured concurrency

A value bound in a scope is visible to every subtask forked inside it — the intended way to propagate request context to concurrent work (see Structured concurrency).

ScopedValue.where(CURRENT, user).run(() -> {
  try (var scope = StructuredTaskScope.open()) {
    scope.fork(() -> loadProfile());   // sees CURRENT.get() == user
    scope.fork(() -> loadOrders());    // also sees it
    scope.join();
  }
});

6 · Pitfalls

PitfallReality
Wanting to set() mid-scopeThere is none by design — rebind in a nested where(...).run(...).
get() with no bindingThrows — guard with isBound() or use orElse.
Treating it as a global variableIt only exists inside the scope; that's the safety feature, not a limitation.
Passing a mutable object as the valueThe binding is immutable, but a mutable object it points to can still be mutated — prefer immutable payloads.

Worked example — propagate user + trace id through a request

Legacy — thread every value through params
void handle(Request r) {
  var ctx = new Ctx(authenticate(r), r.traceId());
  service(ctx);                       // must pass ctx...
}
void service(Ctx ctx) {
  repo(ctx);                          // ...and again...
}
void repo(Ctx ctx) {
  log.info("[{}] user={}", ctx.traceId(), ctx.user());  // ...everywhere
}
ScopedValue — ambient, no plumbing
static final ScopedValue<Ctx> CTX = ScopedValue.newInstance();

void handle(Request r) {
  var ctx = new Ctx(authenticate(r), r.traceId());
  ScopedValue.where(CTX, ctx).run(this::service);
}
void service() { repo(); }            // no ctx parameter
void repo() {
  var c = CTX.get();
  log.info("[{}] user={}", c.traceId(), c.user());
}

8 · Cheat sheet

Scoped values in one glance

  • Declare: static final ScopedValue<T> V = ScopedValue.newInstance();
  • Bind: ScopedValue.where(V, value).run(() -> ...) (or .call).
  • Read: V.get(); guard with V.isBound() or V.orElse(default).
  • Immutable — rebind in a nested scope instead of mutating.
  • Auto-unbound on block exit; inherited by forked subtasks.
  • Prefer over ThreadLocal with virtual threads & structured concurrency.
