var — local-variable type inference Java 10

var lets the compiler infer a local variable's type from its initializer. It is syntactic sugar, not dynamic typing — the variable still has one fixed, static type; you simply don't write it out.

staticstill fully typed (not dynamic)

localsonly (+ lambda params in 11)

Java 10(lambda params: 11)
The problem it solves Long generic type names had to be written twice — once on the left, once on the right — (Map<String, List<Customer>> m = new HashMap<…>()), adding noise without adding information. var removes the redundant left-hand type when it's obvious from the initializer, without any change to runtime behaviour or performance.

1 · It's still static typing

2 · Where you can use it

Before
Map<String, List<Customer>> byCity =
    new HashMap<String, List<Customer>>();
for (Map.Entry<String, List<Customer>> e : byCity.entrySet()) { }
try (BufferedReader r = Files.newBufferedReader(path)) { }
After
var byCity = new HashMap<String, List<Customer>>();
for (var e : byCity.entrySet()) { }
try (var r = Files.newBufferedReader(path)) { }
for (var i = 0; i < 10; i++) { }
list.forEach((var s) -> print(s));   // lambda param (Java 11+)

var works for: local variables with an initializer, for/enhanced-for loop variables, try-with-resources, and lambda parameters (11+).

3 · Where you cannot use it

var x;                 // ✗ no initializer — nothing to infer
var y = null;          // ✗ null has no type
var f = () -> 42;      // ✗ lambda needs a target type
var arr = { 1, 2, 3 }; // ✗ array initializer needs a type
public var field = 1;  // ✗ fields cannot use var
var method() { }       // ✗ return types cannot use var
void m(var p) { }      // ✗ method parameters cannot use var

var is local variables only — never fields, method parameters, or return types.

4 · Rules & gotchas

  • Inferred type = the initializer's type, which may be more specific than you want: 
    var list = new ArrayList<String>();   // type is ArrayList<String>, not List<String>
    Declare the interface type explicitly if that matters.
  • Diamond + var: var m = new HashMap<>(); infers HashMap<Object,Object> — usually not intended. Put the type args on the right: var m = new HashMap<String,Integer>();
  • var is not a keyword — it's a reserved type name, so existing variables/methods named var still compile. You just can't name a class var.
  • No effect on generics inference elsewhere — it only names the local.

5 · var vs Object

Object — erases the type
Object o = "hello";
o.length();      // ✗ compile error — only Object methods available
var — keeps the precise type
var s = "hello";
s.length();      // ✓ s is a String, all String methods available

They're completely different: var preserves the exact static type; Object throws it away.

6 · Style: when to use it

Use varAvoid var
Type is obvious from the RHS (new, factory)RHS hides the type (var r = process();)
Long/nested generic typesWhen the explicit type documents intent
Loop indices & iteration variablesWhen you need an interface/supertype, not the concrete class
Local scratch variables with clear namesNumeric literals where the exact type matters (var x = 0; is int)
A good variable name carries the meaning; var just drops the redundant type. var users = userRepo.findActive(); reads fine; var x = f(); does not.

7 · Real-world examples

Before — noisy locals in a real method
Map<String, List<Order>> byCustomer = orders.stream()
    .collect(Collectors.groupingBy(Order::customerId));
for (Map.Entry<String, List<Order>> entry : byCustomer.entrySet()) {
  BigDecimal total = entry.getValue().stream()
      .map(Order::amount)
      .reduce(BigDecimal.ZERO, BigDecimal::add);
  System.out.println(entry.getKey() + ": " + total);
}
After — same code, less noise
var byCustomer = orders.stream()
    .collect(Collectors.groupingBy(Order::customerId));
for (var entry : byCustomer.entrySet()) {
  var total = entry.getValue().stream()
      .map(Order::amount)
      .reduce(BigDecimal.ZERO, BigDecimal::add);
  System.out.println(entry.getKey() + ": " + total);
}

Common good fits: results of stream collect, JDBC/HTTP builders, try-with-resources streams, and test setup with verbose generic types.

8 · Cheat sheet

var in one glance

  • ✅ locals, for / for-each vars, try-with-resources, lambda params (11+).
  • ❌ fields, method params/returns, no-initializer, null, bare lambdas/arrays.
  • Static type = type of the initializer. Not dynamic. No runtime cost.
  • Watch diamond (new HashMap<>() → <Object,Object>) and over-specific concrete types.
  • Use when the type is obvious from the RHS; keep an explicit type when it documents intent.
